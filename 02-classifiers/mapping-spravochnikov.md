## Архитектура: два независимых мастер-справочника

Группа компаний использует **два независимых мастер-справочника**. Каждый решает свою задачу и не требует связки с другим:

| Мастер-справочник | Таблица                       | Записей   | Назначение                                                 |
|-------------------|-------------------------------|-----------|------------------------------------------------------------|
| Мастер ДДС        | `fin_items` (или `eco_items`) | 195 / 172 | Движение денежных средств: бюджет, план-факт, консолидация |
| Мастер затрат     | `cost_items_clean`            | 150       | Начисления: P&L, OPEX, CAPEX, управленческий учёт затрат   |

**Маппинг между мастерами не ведётся.** ДДС и затраты -- принципиально разные измерения:

-  ДДС отражает **фактическое движение денег** (кассовый метод)

-  Затраты отражают **начисления** (метод начисления), в том числе те, которые не сопровождаются движением денег (амортизация, резервы)

Связывать их в одной таблице маппинга нет смысла: одно начисление может не иметь платежа вовсе, один платёж может покрывать несколько статей затрат разных периодов.

## Мастер ДДС: fin_items или eco_items?

Это вопрос выбора формата -- оба варианта содержат одни и те же статьи:

| Вариант | Таблица     | Статей | Особенность                                           |
|---------|-------------|--------|-------------------------------------------------------|
| A       | `fin_items` | 195    | ВГО-статьи как отдельные строки; плоская структура    |
| B       | `eco_items` | 172    | ВГО как атрибут `vg_type`; иерархическое дерево L1–L4 |

Выбор фиксируется методологом и остаётся неизменным для всей группы. Обе таблицы полностью смэплены с бухгалтерским справочником ДДС (`buch_items`).

## Маппинг бухгалтерских статей ДДС -> мастер ДДС

Каждая бухгалтерская статья ДДС из 1С (`buch_items`, 52 статьи) сопоставляется с мастером ДДС через таблицу `buh_to_eco_map`.

### Кардинальность

```
buch_items (52 статьи — укрупнённый уровень РСБУ)
      │
      │  одна BUH → несколько FIN/ECO
      ▼
fin_items / eco_items (195 / 172 статьи — детальный управленческий уровень)
```

Одна бухгалтерская статья ДДС охватывает несколько управленческих, потому что BUH-уровень укрупнённый. Например, BUH-211 «Арендные и лизинговые платежи» -- это аренда зданий, земли, авто, оборудования -- разные статьи в мастере ДДС.

### Текущее состояние маппинга

| Параметр                         | Значение                     |
|----------------------------------|------------------------------|
| Всего записей в `buh_to_eco_map` | 280                          |
| BUH-статей покрыто               | 40 из 52                     |
| BUH-статей без маппинга          | 12 -- требуют инвентаризации |
| FIN/ECO-статей без BUH-привязки  | 2 -- требуют уточнения       |

### Пример

| BUH-код | Наименование BUH                        | FIN/ECO-код | Наименование FIN/ECO                     |
|---------|-----------------------------------------|-------------|------------------------------------------|
| 211     | Арендные и лизинговые платежи           | 01-120101   | Аренда зданий и сооружений               |
| 211     | Арендные и лизинговые платежи           | 01-120102   | Аренда земельных участков                |
| 211     | Арендные и лизинговые платежи           | 01-120801   | Арендные платежи по авто (кроме лизинга) |
| 221     | Уплата НДФЛ в бюджет                    | 01-120603   | НДФЛ, страховые взносы                   |
| 301     | Выручка от продажи внеоборотных активов | 01-110203   | Поступления от реализации ОС             |

## Маппинг бухгалтерских статей затрат -> мастер затрат

Каждая бухгалтерская статья затрат из 1С сопоставляется с мастером затрат (`cost_items_clean`).

Маппинг ведётся **отдельно от маппинга ДДС** -- это независимый процесс для каждой из 7 баз 1С группы компаний.

### Кардинальность

```
Статья затрат 1С (каждой базы — от 20 до 225 статей)
      │
      │  одна или несколько статей 1С → одна статья мастера
      ▼
cost_items_clean (150 статей — единый мастер группы)
```

## Схема потока данных

```
1С каждой базы
    │
    ├── Статья ДДС (buch_items базы)
    │       │
    │       └── buh_to_eco_map
    │               │
    │               ▼
    │           Мастер ДДС (fin_items / eco_items)
    │               └── Отчёт ДДС, бюджет движения денег
    │
    └── Статья затрат (справочник затрат базы)
            │
            └── Маппинг затрат базы → cost_items_clean
                    │
                    ▼
                Мастер затрат (cost_items_clean)
                    └── P&L, OPEX-отчёт, план-факт затрат
```

---

## Правила маппинга

### Для маппинга ДДС (buh -> fin/eco)

1. Каждая BUH-статья должна присутствовать в `buh_to_eco_map` хотя бы одной записью

2. Одна BUH-статья может соответствовать нескольким FIN/ECO-статьям -- это нормально

3. Одна FIN/ECO-статья не должна соответствовать двум разным BUH-статьям

4. Признак контура VGO учитывается на уровне мастера ДДС, а не в таблице маппинга

5. Закрытые правила маппинга не удаляются -- переводятся в `is_active = false`

### Для маппинга затрат (1С -> cost_items_clean)

1. Каждая активная статья затрат из 1С должна быть смэплена на статью мастера

2. Несколько статей 1С могут указывать на одну статью мастера (консолидация дублей)

3. Устаревшие или дублирующие статьи 1С маппятся на ближайшую по смыслу статью мастера

4. При отсутствии подходящей статьи в мастере -- инициировать создание новой через регламент

## Контроль целостности маппинга ДДС

| Проверка                                                        | Статус                      |
|-----------------------------------------------------------------|-----------------------------|
| Все FIN/ECO L4 имеют хотя бы одну BUH-запись в `buh_to_eco_map` | ⚠️ 40/52 BUH покрыто        |
| Все `Parent_ECO_Code` существуют в таблице (нет висячих)        | ✅                           |
| FIN/ECO-статьи с BUH-привязкой                                  | ⚠️ 193/195 (2 без привязки) |
| Дублирующих FIN/ECO на одну BUH-статью нет                      | ✅                           |
