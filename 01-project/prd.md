## 1\. Контекст и цель продукта

### 1\.1. Текущее состояние

Группа компаний ведёт учёт в **8 базах 1С** с несовместимыми справочниками:

| База   | Тип            | ДДС статей | Затрат статей | Роль                        |
|--------|----------------|------------|---------------|-----------------------------|
| 1С:УХ  | Управленческая | 195        | --            | Источник мастера ДДС        |
| КБУ    | Бухгалтерская  | 52         | 150           | Эталон для бух.ДДС и затрат |
| РС     | Бухгалтерская  | 405        | 221           | Привести к мастерам         |
| ГП     | Бухгалтерская  | 357        | 208           | Привести к мастерам         |
| Глоб   | Бухгалтерская  | 99         | 122           | Привести к мастерам         |
| Ворпал | Бухгалтерская  | 125        | 73            | Привести к мастерам         |
| БОС    | Бухгалтерская  | 133        | 36            | Привести к мастерам         |
| Зорг   | Бухгалтерская  | 103        | 20            | Привести к мастерам         |

Итого уникальных статей в бухгалтерских базах: **675 по ДДС, 655 по затратам**. При этом один код нередко означает разные статьи в разных базах -- выявлено 147 конфликтов кодов по ДДС и 124 по затратам.

### 1\.2. Архитектура решения

Два независимых мастер-справочника. Связь между ними не строится.

#### **Мастер ДДС -- двухуровневый:**

```
1С:УХ
  └── fin_items / eco_items (195/172 статьи)
          │   управленческий уровень, иерархия AA-BBGGII
          │   свод бюджетирования и управление ДДС по холдингу
          │
          └── buch_items (52 статьи) ← эталон КБУ
                  │   бухгалтерский уровень РСБУ
                  │   связь: buh_to_eco_map (280 записей, уже сделана)
                  │
                  ├── КБУ — уже соответствует эталону
                  ├── БОС   ─┐
                  ├── Ворпал  │
                  ├── ГП      │─ привести к buch_items (52)
                  ├── Глоб    │
                  ├── Зорг    │
                  └── РС     ─┘
```

Бухгалтерские базы маппятся **только на** `buch_items` -- 52 статьи понятны бухгалтеру в логике РСБУ. Связь с управленческим уровнем (`fin_items`) реализована централизованно через `buh_to_eco_map` и остаётся задачей ФЭС.

**Мастер затрат -- однозначный:**

```
cost_items_clean (150 статей) ← эталон КБУ
    │
    ├── КБУ — уже соответствует эталону
    ├── БОС   ─┐
    ├── Ворпал  │
    ├── ГП      │─ привести к cost_items_clean (150)
    ├── Глоб    │
    ├── Зорг    │
    └── РС     ─┘
```

1\.3. Почему маппинг между мастерами не нужен

ДДС отражает **фактическое движение денег** (кассовый метод). Затраты отражают **начисления** (метод начисления). Одно начисление может не иметь платежа вовсе (амортизация), один платёж может покрывать несколько статей затрат разных периодов. Связывать их в одной таблице -- значит смешивать несовместимые измерения.

1\.4. Связь с 1С:НСИ

ИТ-подразделение внедряет **1С:НСИ**. Данный проект готовит пакет спецификаций для разовой передачи: структура справочников, правила кодирования, иерархия, описание полей, регламент. После передачи -- ответственность ИТ-подразделения.

1\.5. Связь с ВГО и налоговой оптимизацией

Корректная классификация потоков -- необходимое условие для трансфертного ценообразования, консолидированной отчётности и расчёта налоговой нагрузки группы.

4\. Ключевые сущности и структура данных

4\.1. Иерархия мастера ДДС

```
Вид деятельности (AA)
  └── Направление потока (BB)
        └── Группа статей (GG)
              └── Конкретная статья (II)
                    └── Контур консолидации (VG: EXT / VGO)
```

| Код AA | Вид деятельности       |
|--------|------------------------|
| 01     | Операционная           |
| 02     | Финансовая             |
| 03     | Инвестиционная         |
| 04     | Внутренние перемещения |

4\.2. Данные в NocoDB

| Таблица            | Назначение                                             | Записей | Статус           |
|--------------------|--------------------------------------------------------|---------|------------------|
| `fin_items`        | Мастер ДДС управленческий из 1С:УХ (плоская структура) | 195     | ✅ Готов          |
| `eco_items`        | Мастер ДДС управленческий из 1С:УХ (дерево L1–L4)      | 172     | ✅ Готов          |
| `buch_items`       | Мастер бух.ДДС из КБУ (РСБУ, 52 статьи)                | 52      | ✅ Готов          |
| `cost_items_clean` | Мастер затрат из КБУ (очищен)                          | 150     | ✅ Готов          |
| `buh_to_eco_map`   | Маппинг buch_items -> fin_items/eco_items              | 280     | ⚠️ 40/52 покрыто |
| `acc_1c`           | План счетов 1С                                         | 493     | ✅                |

5\. Функциональные требования

F-01. Единая схема кодирования мастера ДДС

-  Все статьи `fin_items` имеют код `AA-BBGGII-VG(EX)`

-  Статьи `buch_items` привязаны к сегменту AA-BB

-  Форматы задокументированы в онтологии

F-02. Полнота маппинга buch_items -> fin_items

-  Все 52 статьи `buch_items` должны иметь записи в `buh_to_eco_map`

-  Текущий пробел: 12 статей без маппинга -- устранить

F-03. Признак контура ВГО

-  Каждая статья мастера ДДС имеет `vg_type`: `EXT` или `VGO`

-  Не влияет на код AA-BBGGII, используется при консолидации

F-04. Мастер затрат -- атрибуты P&L

-  Все 150 статей `cost_items_clean` должны иметь:

   -  `cost_type` -- FIX / VAR

   -  `pl_block` -- OPEX_FIX / OPEX_VAR / DEPR / TAX

   -  `pl_category` -- детальная категория

F-05. Маппинг 6 бухгалтерских баз на мастера

Для каждой из 6 баз (БОС, Ворпал, ГП, Глоб, Зорг, РС):

-  Статьи ДДС базы -> `buch_items` (52 статьи)

-  Статьи затрат базы -> `cost_items_clean` (150 статей)

-  Разрешение конфликтов кодов до начала маппинга

F-06. Статус активности статьи

-  Поле `is_active`: активна / неактивна

-  Неактивные не удаляются -- хранятся для истории

F-07. Контроль целостности

Ежеквартально:

-  0 статей `buch_items` без записи в `buh_to_eco_map`

-  Корректность кода AA-BBGGII (формат, уникальность)

-  Отсутствие дублей по экономической сущности

-  Все статьи `cost_items_clean` имеют атрибуты P&L

-  Полнота маппинга всех 6 баз

F-08. Журнал изменений

-  Каждое изменение: дата, инициатор, согласующий, причина, версия

-  Код AA-BBGG действующей статьи изменению не подлежит

F-09. Пакет спецификаций для 1С:НСИ

**1\. Документ в Gramax** -- структура, поля, правила кодирования, регламент

**2\. Экспорт из NocoDB** -- JSON через REST API, только активные статьи

**3\. Excel-выгрузка** -- лист на каждый справочник + лист маппинга

**Критерий:** ИТ загружает справочники в 1С:НСИ без дополнительных уточнений у методолога.
