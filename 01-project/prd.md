# PRD: Единый справочник финансовых статей группы компаний

**Версия:** 1.0
**Дата:** 15 марта 2026
**Статус:** Draft

---

## 1. Контекст и цель продукта

### 1.1. Проблема

Группа компаний (строительство + операционные бизнесы) ведёт управленческий учёт в условиях фрагментированной классификации финансовых потоков:

- **Два несвязанных справочника ДДС**: бухгалтерский (52 статьи, РСБУ) и финансовый (195 статей, управленческий). Несовместимые форматы кодов, 6 финансовых статей без бухгалтерского аналога — суммы выпадают из сводных отчётов.
- **Справочник затрат** (cost_items, 167 позиций): у 65 записей отсутствуют коды, инвестиционные статьи не охвачены.
- **Нет сквозной иерархии**: данные из 1С → ЭОС → управленческий учёт соединяются вручную, без единого ключа классификации.
- **Отсутствие регламента изменений**: справочники меняются локально, накапливаются расхождения.

### 1.2. Цель

Создать **единый нормализованный классификатор финансовых потоков и затрат**, который:
- служит мастер-справочником для всех систем (1С:УХ, 1С:Бухгалтерия, BI);
- обеспечивает автоматическую свёртку управленческих данных до регламентированной отчётности (РСБУ);
- поддерживает консолидацию с устранением внутригрупповых оборотов (ВГО);
- управляется по утверждённому регламенту;
- служит **готовой спецификацией для передачи в 1С:НСИ** — единый источник достоверных данных в системах 1С группы компаний.

### 1.3. Связь с 1С:НСИ

ИТ-подразделение группы внедряет **1С:НСИ** — корпоративную систему нормативно-справочной информации (справочники номенклатуры, контрагентов, статей затрат и ДДС), которая обеспечивает единообразие данных и исключает дубли во всех экземплярах 1С.

Данный проект решает задачу **подготовки пакета спецификаций** для ИТ-подразделения — структура справочников, правила кодирования, иерархия, описание полей и регламент ведения — в формате, пригодном для загрузки в 1С:НСИ.

**Передача разовая.** После передачи ответственность за поддержание актуальности данных в 1С:НСИ переходит к ИТ-подразделению. Изменения в справочниках инициируются через регламент (см. F-07) и передаются в НСИ по согласованному процессу.

### 1.4. Связь с налоговой оптимизацией и ВГО

Проект является **инфраструктурной основой** для проекта «ВГО и налоговая оптимизация»: корректная классификация потоков — необходимое условие для трансфертного ценообразования, расчёта налоговой нагрузки и консолидированной отчётности группы.

## 3. Область охвата (Scope)

### В рамках проекта:
- Нормализация и объединение справочников: `fin_items`, `buch_items`, `cost_items`, `eco_items`
- Внедрение единой схемы кодирования `AA-BBGGII-VG(EX)`
- Маппинг: `buh_to_eco_map` — связь бухгалтерских статей с управленческими
- Регламент ведения справочников (уже разработан, требует утверждения)
- NocoDB — интерфейс для бухгалтера и руководителя: просмотр, правки, дистанционное согласование
- Gramax (https://gramax.leval907.space/tax_planning_alyans) — публикация регламентов и документации для бизнеса
- **Пакет спецификаций для 1С:НСИ** (разовая передача ИТ-подразделению):
  - Документ в Gramax: структура справочников, иерархия, правила кодирования, описание полей, регламент
  - Экспорт из NocoDB: актуальные данные справочников в структурированном виде (JSON / API)
  - Excel-выгрузка: для загрузки и сверки на стороне ИТ / 1С

### За рамками проекта (v1):
- Автоматическая синхронизация с 1С:НСИ после разовой передачи (ответственность ИТ-подразделения)
- Автоматическая выгрузка из 1С (ручной ввод допустим на старте)
- Разработка BI-дашбордов (следующая фаза)
- Модуль управления договорами и КС-2 (отдельный продукт)

## 4. Ключевые сущности и структура данных

### 4.1. Иерархия классификатора

```
Вид деятельности (AA)
  └── Направление потока (BB)
        └── Группа статей (GG)
              └── Конкретная статья (II)
                    └── Контур консолидации (VG: EXT / VGO)
```

**Коды вида деятельности (AA):**
| Код | Значение |
|---|---|
| 01 | Операционная деятельность |
| 02 | Финансовая деятельность |
| 03 | Инвестиционная деятельность |
| 04 | Внутренние перемещения |

### 4.2. Данные в NocoDB

NocoDB выполняет роль **интерфейса для нетехнических пользователей** (бухгалтер, руководитель) и **API-источника** для скриптов и интеграций. Не является учётной системой.

| Таблица | Назначение | Записей |
|---|---|---|
| `fin_items` | Финансовый справочник ДДС (управленческий) | 195 |
| `buch_items` | Бухгалтерский справочник ДДС (РСБУ) | 52 |
| `eco_items` | Экономический справочник (детальный уровень) | 242 |
| `cost_items` | Статьи затрат для P&L | 167 |
| `cost_items_2` | Статьи затрат v2 (+ nu_type) | 214 |
| `buh_to_eco_map` | Маппинг бухгалтерских → управленческих статей | 280 |
| `acc_1c` | План счетов 1С | 493 |

## 5. Функциональные требования

### F-01. Единая схема кодирования
- Все управленческие статьи должны иметь код формата `AA-BBGGII-VG(EX)`
- Бухгалтерские статьи: трёхзначный код (существующий формат) + явная привязка к сегменту AA-BB
- Таблица соответствия форматов задокументирована в регламенте

### F-02. Полнота маппинга FIN → BUH
- Каждая финансовая статья обязана иметь ровно одну бухгалтерскую (1:1 в сторону FIN→BUH)
- 6 непривязанных статей: провести инвентаризацию и устранить до запуска
- Система должна выявлять и сигнализировать о нарушениях связи

### F-03. Признак контура ВГО
- Каждая статья имеет атрибут `vg_type`: `EXT` (внешний) или `VGO` (внутригрупповой)
- Признак не влияет на код AA-BBGGII, является отдельным измерением
- Используется при консолидации для элиминации ВГО

### F-04. Справочник затрат (P&L)
- Все 167 статей `cost_items` должны иметь заполненные коды (`cost_item_code`)
- Добавить инвестиционные статьи (текущий gap: отсутствуют в cost_items)
- `cost_items_2` (214 записей, + `nu_type`) — проверить на дублирование и влить в мастер

### F-05. Статус активности статьи
- Статья может быть: `Активна` / `Неактивна`
- Неактивные статьи не удаляются — сохраняются для истории
- При неактивации: дата, причина, инициатор фиксируются в журнале

### F-06. Контроль целостности (аудит)
- Ежеквартальные проверки:
  - Нет FIN-статей без BUH-аналога
  - Корректность кода AA-BBGGII (формат, уникальность)
  - Отсутствие дублей по экономической сущности
  - Корректность VG-признака
- Результат проверки: отчёт с перечнем нарушений

### F-07. Журнал изменений
- Каждое изменение справочника фиксируется: дата, инициатор, согласующий, причина, версия
- Код AA-BBGG действующей статьи изменению не подлежит
- Допускается уточнение наименования и описания

### F-08. Пакет спецификаций для 1С:НСИ
Разовая передача ИТ-подразделению для загрузки справочников в 1С:НСИ. Пакет включает:

**1. Документ-спецификация в Gramax:**
- Описание каждого справочника: назначение, поля, типы данных, обязательность
- Иерархия классификатора (AA–BB–GG–II) и правила кодирования
- Таблица соответствия: управленческие статьи (FIN) ↔ бухгалтерские (BUH)
- Регламент ведения: кто инициирует изменения, кто утверждает, как передаются в НСИ

**2. Экспорт из NocoDB:**
- Полные данные справочников через REST API (`fin_items`, `buch_items`, `cost_items`, `buh_to_eco_map`)
- Только активные статьи, структурированный JSON

**3. Excel-выгрузка:**
- Отдельный лист на каждый справочник
- Все поля включая коды, наименования, иерархию, статус, признак VG
- Лист маппинга FIN → BUH для загрузки связей в НСИ

**Критерий готовности пакета:** ИТ-подразделение может загрузить справочники в 1С:НСИ без дополнительных уточнений у методолога.
