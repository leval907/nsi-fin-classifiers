## Что передаётся

Пакет спецификаций для загрузки справочников финансовых статей в 1С:НСИ включает три компонента:

| Компонент | Формат | Назначение |
|-----------|--------|------------|
| Документация Gramax | Web (https://gramax.leval907.space/tax_planning_alyans) | Описание структуры, полей, правил, регламент |
| Экспорт из NocoDB | JSON (REST API) | Машиночитаемые данные для загрузки / интеграции |
| Excel-выгрузка | .xlsx | Для загрузки вручную и сверки на стороне ИТ |

---

## Состав Excel-выгрузки

Файл передаётся как единый `.xlsx` со следующими листами:

1. **fin_items** — 195 строк, все поля включая `fin_code`, `vg_type`, `buch_code`
2. **buch_items** — 52 строки, все поля включая `buch_code`, `group_code`
3. **cost_items** — 167 строк, все поля включая `cost_item_code`, `pl_block`, `nu_type`
4. **buh_to_eco_map** — 280 строк, все правила соответствия BUH → ECO
5. **Маппинг FIN → BUH** — сводная таблица для загрузки связей между справочниками

Все листы содержат строку-заголовок с именами полей.

## Порядок действий для ИТ-специалиста

### Шаг 1. Получение пакета

- Уточнить у ответственного от ФЭС актуальную ссылку на Excel-файл и API-доступ к NocoDB
- Убедиться, что файл содержит актуальные данные (дата обновления указана в письме передачи)

### Шаг 2. Сверка состава

Перед загрузкой проверить:
- Количество строк в каждом листе совпадает с ожидаемым (см. таблицу выше)
- Нет пустых обязательных полей (исключение: `cost_item_code` — уточнить у ФЭС)
- Форматы кодов корректны: `fin_code` = AA-BBGGII (8 символов + разделитель), `buch_code` = 3 цифры

### Шаг 3. Загрузка в 1С:НСИ

Рекомендуемая последовательность загрузки справочников:

1. **buch_items** (52 записи) — «Статьи ДДС, регламентированные»
2. **fin_items** (195 записей) — «Статьи ДДС, управленческие»
3. **Маппинг FIN → BUH** — настройка соответствий между справочниками
4. **cost_items** (167 записей) — «Статьи затрат»
5. **buh_to_eco_map** (280 записей) — правила автоматической трансляции

### Шаг 4. Проверка после загрузки

После загрузки выполнить контрольные проверки:
- Количество загруженных записей совпадает с переданным файлом
- Иерархия fin_items отображается корректно (4 уровня: AA → BB → GG → II)
- Связи маппинга работают: выбор fin_code подтягивает соответствующий buch_code
- Статьи с `is_active = false` не отображаются в рабочих справочниках 1С

### Шаг 5. Подтверждение

По завершении загрузки уведомить ФЭС об успешной передаче с указанием:
- Даты загрузки
- Количества записей по каждому справочнику
- Выявленных расхождений или ошибок (если есть)

---

## Критерий успешной загрузки

Загрузка считается успешной, если выполнены все условия:

- [ ] Все 195 статей fin_items загружены без ошибок
- [ ] Все 52 статьи buch_items загружены без ошибок
- [ ] Все 167 статей cost_items загружены (статьи без кода — отдельным согласованным файлом)
- [ ] 280 правил маппинга buh_to_eco_map загружены
- [ ] Связь fin_items → buch_items работает корректно
- [ ] Тестовый пользователь может выбрать статью ДДС при вводе документа в 1С

## Контактное лицо от ФЭС

По всем вопросам, связанным со структурой и содержанием справочников, обращаться в финансово-экономическую службу.

Вопросы по технической реализации (формат загрузки, API, ошибки импорта) — в ИТ-службу.

---

## Важно: разграничение ответственности

**ФЭС отвечает за:**
- Корректность содержания справочников (коды, наименования, классификация)
- Инициирование изменений в справочниках
- Своевременную передачу обновлений в ИТ-подразделение

**ИТ-служба отвечает за:**
- Техническую загрузку в 1С:НСИ
- Поддержание актуальности данных в 1С:НСИ после первичной передачи
- Настройку интеграции с другими системами 1С

После завершения первичной передачи пакета последующие изменения в справочниках инициируются ФЭС в соответствии с регламентом управления изменениями (см. раздел «Регламенты»).
